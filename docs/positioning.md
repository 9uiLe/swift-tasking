# 用途と設計原則

## 達成すること

Tasking の中心は、同期イベントから開始した非構造化タスクを、キャンセル済みも含めて実終了まで所有し、
所有者の終了時に新規受付を止めて終了を待てることである。
タスクの管理と、業務結果・進捗・エラー表示・再試行の判断を分け、利用者が把握する契約を小さく保つ。

## 標準の寿命管理から選ぶ

| 必要な能力 | 選択と理由 |
|---|---|
| async 関数内で子の終了まで合流する | `async let` / task group。スコープが所有と終了待ちを表す |
| SwiftUI の表示や検索語に連動する | `.task` / `.task(id:)`。表示と入力の変化にキャンセルを接続できる |
| 1つの async 操作の多重呼び出しを防ぐ | 通常の async 関数と状態ガード。業務状態と受付を同じ場所で表す |
| 同期コールバックから開始し、後からキャンセル・終了確認する | `ViewTaskStore`。開始元を越えてタスクのハンドルを所有する |
| 複数の async 入口で Action 単位の受付を共有する | `ActionRunner`。呼び出し元のタスクを維持したまま実行数を数える |
| 非 UI サービスが差し替え可能な処理を所有する | `TaskSlot`。Action や MainActor を持ち込まず、所有と終了を管理する |

[検索例](../Examples/TaskingPrototype/Sources/TaskingPrototype/SearchFeature.swift) は `.task(id:)` と入力のデバウンスを使う。
[課金情報の例](../Examples/TaskingPrototype/Sources/TaskingPrototype/BillingFeature.swift) は通常の async と状態ガードを使う。
[アプリ同期の例](../Examples/TaskingPrototype/Sources/TaskingPrototype/AppSyncFeature.swift) は画面を越える所有に Store を使う。

## 設計の境界

### 所有を必要な場所に置く

Store と Slot は Task を作成し、キャンセルを要求してもハンドルを実終了まで保持する。
Runner は Task を作らず、呼び出し元のタスク内で処理する。所有を必要としない入口へ Store を追加しない。
通常は寿命ごとに所有者と Store を分ける。`CancellationGroup` は、同じ Store 内の一部を選ぶ必要がある場合だけ使う。
グループ名から画面寿命や OS の実行権限を推測する必要をなくす。

### 受付と実終了を結び、追跡は明示する

キャンセルは強制停止ではない。Store の既定 `.ignoreNew` は、キャンセル済みでも同じ ActionID の未終了処理が
あれば次の要求を拒否する。保存の副作用を旧処理の実終了前に重ねないためである。

一方、更新をすぐ始めたい要求には `.cancelExisting` が使える。キャンセルした処理の終了を待たないため、
協調しない旧処理が新規要求を無期限に妨げることを避けられる。その場合の結果採用と副作用の順序は利用側が決める。
選択の正確な契約は [アーキテクチャ](architecture.md#開始方針と照会) に定める。

### 標準 Swift のキャンセルとエラーを保つ

キャンセルには `Task.checkCancellation()` / `Task.isCancelled` と対応 API を使う。
パッケージ固有のキャンセル引数は導入せず、標準 `.task` とライブラリの処理から同じ async メソッドを呼べるようにする。
Runner は成功値と元のエラー型を維持し、重複拒否だけを外側の Optional で表す。
Store の未処理エラー通知も元のエラーを渡す。値の型消去や業務向けの独自結果モデルを要求しない。

### 管理状態と表示状態を分ける

追跡と未終了件数は、その瞬間の管理状態を返す同期照会であり、UI の読み込み表示ではない。
Store と Runner は `Observable` / `ObservableObject` にせず、Observation や Combine に依存しない。
ViewModel が全終了経路の表示を確定し、重なる処理は世代で保護する。

## 適用範囲

キューによる順序保証、同時実行数の上限、永続化、プロセス終了後の再開、OS のバックグラウンド実行は、
それぞれの仕組みを使う。キャンセルは送信済みの副作用を巻き戻さない。
MainActor 上の重い同期計算や大量の開始は、その時間を占有する。開始前のデバウンス・集約と、処理を担当する actor の隔離を確認する。

Tasking は MIT ライセンスのライブラリであり、タスク所有のリファレンス実装でもある。
導入の判断は型の数や記述量だけでなく、利用側が持つ状態、識別子、キャンセル規則、終了確認が減るかで行う。
