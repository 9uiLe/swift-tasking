# ADR-0013: 追跡索引と所有台帳に更新規則を集約する

## 前提

Store と Runner は Action を追跡し、Store と Slot はタスクを所有する。
同じ責務の登録・照会・解除の規則を、共通の内部型で表す。

## 決定

| 内部型 | データ | 利用方法 |
|---|---|---|
| `ActionRuns<Metadata>` | `[ActionID: [ActionRunID: Metadata]]` | Store は寿命ラベル、Runner は `Void` を格納する |
| `OwnedTasks<Key>` | タスクのハンドルと所有識別子 | Store は `ActionRun`、Slot は `TaskOwnership` をキーにする |

タスクの作成、actor 隔離、受付方針、待機ループは各公開型が担当する。
台帳への可変アクセスは中断点をまたがせず、タスクの終了処理が所有者の actor に入る前に登録を完了する。

## 不変条件

- Store の追跡中の実行は、必ず所有中である。
- 個別の実行は ActionID と ActionRunID の組で選択する。
- 古い実行の終了は、その実行だけを索引と台帳から除く。
- 内部タスクは所有者を弱参照し、解放時のキャンセルを妨げない。

## 理由と制約

追跡索引は重複とラベルの選択、所有台帳はハンドルの保持とキャンセルを担当する。
キャンセル済みタスクの別台帳への移動や、複数の追跡索引の同期を必要としない。

内部型は公開インターフェースに含めず、利用者は Store・Runner・Slot を通じて操作する。
自己待機の識別子と照会のコストは [ADR-0015](0015-measured-ownership-overhead.md) に定める。
