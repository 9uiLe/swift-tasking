# ADR-0009: キャンセル時に重複判定から外す

## 前提

キャンセル要求は処理の停止時点を確定しない。
Store では、新しい要求を受け付ける判断と、既存のタスクの終了確認を独立して扱う。

## 決定

`cancel(run)`・`cancel(id:)`・`cancel(lifetime:)` は、対象となる追跡中の実行を直ちに除き、
そのタスクにキャンセルを要求する。`cancelAll()` は追跡を空にし、所有中のすべてのタスクに要求する。
ハンドルの所有は、各タスクの終了まで続ける。

重複方針と `isRunning` / `runningCount` は追跡状態を参照する。
`.ignoreNew` は、追跡中の同じ ActionID があるときに新しい要求を拒否する。

## 理由と制約

キャンセルした処理が終了に時間を要しても、新しい要求の受付を判断できる。
キャンセル済みの処理を終了まで重複と扱う場合は、協調しない処理が次の要求を無期限に妨げてしまう。

手動キャンセル直後の `.ignoreNew` と `.cancelExisting` は、古い処理が終わる前に新しい処理を開始できる。
副作用の順序や結果の採用は利用側が管理する。
追跡解除後の終了待ちは [ADR-0012](0012-store-tracking-and-ownership.md) に定める。
