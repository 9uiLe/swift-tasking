# ADR-0010: 非 UI の差し替え可能なタスクを Slot が所有する

## 前提

サービスは、メソッドの呼び出しを越えて処理を続け、次の要求でその処理を差し替える場合がある。
その所有管理には、UI の寿命ラベルや ActionID を必要としない。

## 決定

`TaskingCore` に `TaskSlot` actor と `CancellationContext` を置く。
Slot は最大1つのアクティブなタスクを持ち、`replace` でキャンセルを要求して新しいタスクを開始する。
差し替え済み・キャンセル済みのタスクも終了まで所有し、`waitForIdle()` はその全体を待つ。

処理本体はエラーを外に投げない async クロージャとする。
任意の優先度を `Task` に渡し、`nil` では呼び出し元の優先度を継承する。
受付の閉鎖と終了待ちは [ADR-0011](0011-task-slot-close-and-self-wait.md) に定める。

## 理由と制約

所有規則を単一のアクティブなタスクに限定し、サービスが必要な管理を小さなインターフェースで表せる。
業務エラー、デバウンスの時間、再試行、蓄積した処理の確定、結果状態はサービス側が持つ。

アクティブなタスクは最大1つでも、未終了の処理は複数存在できる。
到着順の実行や最新の結果だけの採用は保証しないため、世代管理と副作用の順序を利用側で定義する。
