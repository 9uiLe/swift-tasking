# ADR-0016: 所有者認証とコミット単位の検証で公開する

## 前提

SwiftPM は Git タグを配布ソースとして参照する。
タグの作成時点で取得可能になるため、GitHub Release を公開する前からソースの妥当性を確定する必要がある。
`Tasking` と `TaskingCore` は同じ package として、1つのバージョンで配布する。

## 決定

- 所有者が安定版の SemVer を選び、ローカルの GitHub CLI 認証で操作する。
- `prepare` は取得した master の SHA から文書の準備 PR を作り、公開はマージ後に行う。
- `check` と `publish` は、対象 SHA の master push CI で Swift とリリースツールの両ジョブの成功を要求する。
- CHANGELOG、日本語・英語両 README の依存、注釈付きタグ、Release 本文を同じ版に揃える。
- 準備と公開検証では、README の欠落・依存指定の重複・番号の不一致を拒否する。
- 準備 PR と Release 本文は日本語で作成する。
- 検証、タグ作成、ドラフト作成、照合、immutable Release の公開の順に実行する。
- タグがある場合はそのコミットから再開し、競合するタグや Release は上書きしない。
- GitHub Actions は検証専用とし、公開資格情報を持たない。

## 理由と制約

公開対象のコミットで成功した CI を参照するため、リポジトリ・ワークフロー・イベント・ブランチ・SHA・実行回を照合する。
PR 用の成功や、失敗前の古い成功は公開判断に使わない。

ネットワーク越しのタグと Release の作成は、全体を1つの操作として巻き戻せない。
作成済みタグを公開対象の固定点にすることで、一度取得可能になったソースを変えずに再開できる。

公開の判断と操作は所有者が行う。設定・コマンド・復旧方法は [リリース設計と運用](../releasing.md) に定める。
