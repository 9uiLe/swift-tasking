# ADR-0011: Slot の受付停止と終了待ちを定義する

## 前提

actor は中断中にほかの呼び出しを受け付ける。
サービスの終了時は、待機を始める前に差し替えの受付を止める必要がある。
また、所有される処理が自分の終了を待つと、待機を完了できない。

## 決定

- `close()` は受付を恒久的に閉じる。繰り返し呼べ、既存の処理はキャンセルしない。
- 閉鎖後の `replace` は処理本体を呼ばず、`false` を返す。
- `cancelAndWaitForIdle()` は中断前に受付を閉じ、アクティブなタスクをキャンセルして、全所有タスクを待つ。
- `waitForIdle()` は差し替え済みの処理と、受付が開いていれば待機中に開始した処理も待つ。
- 自己待機は TaskLocal の所有文脈で検出する。Debug ではアサーション、Release ではその文脈を待機対象から除外する。

## 理由と制約

受付停止を最初の中断点より前に行うことで、終了待ち中の新規開始を防げる。
閉鎖とキャンセルを分けるため、`close()` と `waitForIdle()` による自然完了待ちも表現できる。
再利用するキャンセルには `cancel()` を使う。

所有文脈は構造化子タスクにも継承される。自己待機はプログラミング上の契約違反であり、通常の制御フローには使わない。
検出は任意のタスク間の循環待機を解決しない。
待機側のキャンセルは所有する処理に伝播せず、待機も中断しない。終了しない処理があれば待機も続く。
