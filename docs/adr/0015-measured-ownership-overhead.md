# ADR-0015: 所有識別と照会のコストを限定する

## 前提

Store の同期操作は MainActor の時間を使い、Slot は差し替えごとに所有識別子を作る。
識別子の寿命と正しさを保ちつつ、生成と走査の負担を必要な範囲に収める。

## 決定

- 公開する `ActionRunID` は UUID に基づく値とする。
- 内部の `TaskOwnership` は不変の final class とし、等価性に参照の一致、ハッシュに `ObjectIdentifier` を使う。
- 所有台帳と TaskLocal が識別子を保持し、識別子は Store や Slot を参照しない。
- 寿命ラベルの存在確認は最初の一致で返し、件数照会は全件を走査する。
- 所有文脈が空なら、自己待機の除外対象を探す走査を行わない。
- 追跡情報は単一の索引に置き、寿命ラベル用の追加索引を持たない。
- 所有台帳の内部表現を `@inlinable` / `@usableFromInline` で公開しない。

## 理由と制約

独立した参照識別子は乱数生成を必要とせず、TaskLocal に残る間はアドレスが再利用されない。
所有者自身のアドレスだけを識別子にすると、所有者の解放後に継承先へ残る値と再利用アドレスを区別できない。

存在確認の早期終了は一致率に依存する。一致しなければ全件を走査し、件数照会より遅い条件もある。
追加索引は照会を定数時間にできる一方、登録・キャンセル・終了ごとに同期が必要になる。
採用は実アプリケーションで照会が支配的かを測って判断する。

内部表現の公開は保守の制約を増やす。インライン化指定の11回比較では明確な利益が示されておらず、
そのコストを引き受ける根拠にはならない。
比較する実装の定義と測定条件は [性能特性](../performance.md) に記録する。
